# 转换与修补：按当前任务查阅

## TXT 与 PDF 导出文本

`txt2filing.py` 用现成样式和页眉页脚 API，将每个非空源行写为一个段落。支持 UTF-8（含 BOM），不自动猜编码；解码失败时确认编码后转成 UTF-8 再运行。

- `--profile 申报文件`：001/002/003/004/011 与 005 正文样式族。
- `--profile 招股说明书`：Heading1～5 与 BodyIndent 样式族。
- 保留原文序号，不生成新序号。其他体裁或新编号体系需要局部定制，不传不支持的 profile。
- 默认保留文本表，不重建为 Word 表格；需要可编辑表格时使用 Markdown 转换器或 Python 表格 API。
- `--drop-tables` 删除带横线分隔的对齐表、Markdown 管道表的表头、分隔线及连续数据行。空行、页分隔符、非表格行结束该范围。`--inspect --drop-tables` 输出 1 起算、两端包含的删除行号范围。
- 删除表格不等于删除相邻的“如下表所示”、单位、注释或签字内容；脚本保留这些文字。连续多行表头中只有紧邻分隔线的一行能被识别，其他行保留。无分隔线的表格、跨页续表、单列续行、OCR 错位需抽查并局部标定；统计不证明已删净全部表格。
- PDF 导出分隔符 `========== 第 N 页 ==========` 自动去掉；静态目录页码、正文中嵌入的旧页码和断行不自动改写。需要刷新目录时，先定位并替换旧目录，再用 `F.add_toc()`，最后在 Word 中更新。
- 默认不新建封面、目录、发行人或报告期。可通过 `--header` 指定已知页眉、`--footer-prefix` 指定已知文件编号；缺少信息时使用文件名页眉及无前缀页码。

回归场景：长篇 TXT 要求删表并转成招股书格式，先 `--inspect --drop-tables`，再转换；查看删除范围附近内容，必要时只修遗漏区域。已有明确处理方式后执行，不把全文逐段手工重写为生成代码。

## Markdown 转招股书

使用 `md2prospectus.py`。H1 为封面标题，H2/H3/H4 对应标题 1/2/3；脚本剥离原序号后规范编号。标题优先级为用户明确的 `--title` > 原文 H1 > 文件名，不自行缩短标题。

脚本会建立部分“第 N 节”引用映射。需要核对交叉引用时，只检查受编号变动影响的位置，不把原文引用全部推翻重写。

已知限制：`--no-cover` 模式的 H1 会在正文中使用一级标题样式；有多个 H1 或特殊标题层级时，先局部规范 Markdown。正文、列表、代码和表格按输入结构处理。内容核对扣除 Markdown 标记及明确的编号变化。

封面节 `titlePg` + 页码 start=0，不写封面页眉页脚；正文节 start=1 并移除继承的 `titlePg`。目录域需要 Word 更新才能有真实页码；生成成功时不声称目录已经更新。

## DOCX 修补

`format_existing.py` 同时注入标准样式、逐段分类并格式化表格。`filing_docx.py apply` 只替换标准样式定义、设置页面等，不重分段落类别。两者是可选路径，不需要先 apply 再 format。

一般修补脚本适用于原稿已有合理段落结构的申报文件。保留封面大字、目录样式与已挂标准样式的段落；不典型标题只调整局部归类。不用它将公告改成申报文件，或在标题族之间迁移全文。

已有自动编号时先保留它及文字的关联。通用 `format_existing.py` 和 `apply` 会清除或重建编号定义，`--auto-numbering` 表示注入插件编号，不表示保留原编号。需要保留时，在副本上只调整所需样式属性和表格，不调用 `write_numbering`／`drop_numbering`，也不整体替换含编号绑定的样式；检查时加 `--auto-numbering`。若需转换为手写，先把显示的编号写入文本，再去掉绑定，并核对编号。

`fix_announcement.py` / `fix_guide.py` 分别处理两种仿宋体裁。公告标题黑体、正文 15pt 固定 28 磅；公文一级标题加粗仿宋、正文 14pt 固定 30 磅。公告符号、原有编号属于可见内容。

通用修补脚本不向表前空段补写推断的单位。单位、标题和数值均属于原文内容。

## 长表与实际分页

`format_table` 已按行数处理长表；≥40 行允许行内分页，≥60 行倾向保留原行高和边距。公文索引表保留已有单元格对齐，表头跨页重复。签字表、落款表不强套数据表规则。

分页变化不等于错误。只有用户要求维持页数或实际渲染发现问题时，才检查长表行高、单元格边距、行内分页及正文行距。不为了复现某份历史文件的页数反复导出。

## 选择检查强度

- 普通交付：匹配 profile 的 `check` + 文字完整性比对。
- 维护脚本或明确严格检查：再加 `--strict`，按具体 FAIL 处理。
- 实际分页／目录验收：环境支持时做 Word／PDF 渲染；只对受影响区域检查。

仅检查格式的任务不自动接受修订、删除批注或重算金额。新建内容如需统一数字显示格式，遵循用户指定的千分位、精度和零值约定；既有金额不因排版规则改写。
